# 決策紀錄

## ADR-001：網頁原型採 Vite + 原生 TypeScript

- 日期：2026-11-11
- 決定者：GPT（專案技術負責）
- 狀態：採用
- 決定：前端使用 Vite、原生 TypeScript 與 CSS，不導入 React 等 UI 框架。
- 理由：符合純前端與零成本要求；單人專案依賴少、學習與維護負擔低；可直接部署至 GitHub Pages 或 Cloudflare Pages。
- 後果：未來介面狀態變複雜時，需重新評估元件框架，但原型階段不先承擔成本。

## ADR-002：第一版採規則式、本機風險分析

- 日期：2026-11-11
- 決定者：GPT（專案技術負責）
- 狀態：採用
- 決定：先用可讀的關鍵話術與網址格式規則，所有分析只在瀏覽器執行。
- 理由：可快速驗證使用者是否看得懂原因與建議，也遵守隱私原則；正式模型需等測試集與評估流程建立後再導入。
- 後果：目前只能提供風險提醒，不代表準確判定；必須持續量測誤報與漏報。

## ADR-003：使用「安心查」作為工作名稱

- 日期：2026-11-11
- 決定者：GPT（暫定）
- 狀態：待擁有者確認
- 決定：開發期間以「安心查」呈現產品，避免使用過度恐嚇或保證安全的名稱。
- 理由：名稱簡單、對長輩易懂，也呼應「不確定就先查」的產品行為。
- 後果：商標、網域與正式品牌尚未檢索或承諾，擁有者可隨時更名。

## ADR-004：可信平台先採外部連結，不自動送出查詢

- 日期：2026-11-11
- 決定者：GPT（專案技術負責）
- 狀態：採用
- 決定：數發部、165、刑事局、MyGoPen 與聯徵中心先以清楚標示的外部連結呈現，不把使用者輸入內容自動傳給第三方。
- 理由：各來源的 API、再利用授權與商業條件尚未完整確認；外部連結可立即提供求助價值，同時維持本地處理承諾。
- 後果：使用者需自行在外部平台再次輸入；未來只有在授權、隱私告知與技術條件都確認後才考慮串接。

## ADR-005：下載政府開放資料，掃描時查本機快照

- 日期：2026-11-11
- 決定者：GPT（專案技術負責）
- 狀態：採用
- 決定：由更新腳本下載數位產業署與警政署三份政府開放資料，正規化並去重成版本化 JSON；前端掃描時只搜尋隨網站發布的本機快照。
- 理由：三份資料皆標示政府資料開放授權條款第 1 版；本機查詢可避免送出使用者訊息，也不依賴來源網站的 CORS、臨時故障或頁面改版。
- 後果：資料新鮮度取決於更新腳本執行頻率；結果必須顯示資料庫版本，未命中也不能宣稱安全。

## ADR-006：每日更新必須通過品質閘門才提交

- 日期：2026-11-11
- 決定者：GPT（專案技術負責）
- 狀態：採用
- 決定：GitHub Actions 每日更新後，必須通過資料完整性驗證、自動測試與正式建置；只有資料內容改變時才由 `github-actions[bot]` 提交。
- 理由：政府端點可能暫時回傳錯誤頁、空資料或格式改變，不能讓自動化把壞資料直接發布。
- 後果：驗證門檻設為至少 100,000 個唯一網域，且三個來源各有合理最低列數；未來來源規模明顯變化時需調整門檻。

## ADR-007：公開原型使用 GitHub Pages

- 日期：2026-11-11
- 決定者：GPT（專案技術負責）
- 狀態：採用
- 決定：使用 GitHub Pages 發布公開網址；同一個 Actions 工作流程負責程式推送部署與每日資料更新後重新部署。
- 理由：原型期零成本、任何人可開啟，並能讓資料更新與網站版本保持一致。
- 後果：網站需使用相對資源路徑以支援 GitHub Pages 的 repository 子路徑；正式品牌網域留待公開版前處理。
