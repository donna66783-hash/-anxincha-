## 已實作

- 每張卡片保留 `image_id`、順序、原始 OCR、人工修正、修正狀態、文字來源、風險狀態及命中訊號。
- 可查看／修正辨識文字、只重新分析該張、恢復原始 OCR；其他圖片不重跑 OCR，整批最高狀態與同一對話整合會重算。
- 即使 OCR 空白也可人工輸入；畫面明示「依使用者修正文字分析」，OCR 信心不會因修正而提高。
- 補充文字預設是獨立背景，可指定單張；只有勾選同一段對話後才能指定整組。
- 來源標籤區分自動 OCR、人工修正、使用者補充、QR、政府歷史、社群案例及本機語意提示。
- 行為組合涵蓋贈送誘因、外部網域、物流／訂單填寫、平台脈絡與金融認證；正常朋友贈送、官方寄件教學及防詐宣導有反向測試。
- 網址剖析不再把緊鄰網址的中文轉成假 IDN；保留使用者原始網址字串供說明。

## OCR 流程與限制

- 每張先保留原圖候選；低於 900 px 的圖片最多加入 3 倍放大與灰階對比候選；長圖加入頭尾兩段；一般圖加入一個對比候選。
- 每一技術嘗試最多 3 個候選；若辨識引擎本身中斷，最多重新啟動一次。單純「沒有文字」不再重跑。
- 單一 OCR 輸入上限 1,200 萬像素；圖片仍維持每張 20 MB、整批 80 MB、最多 10 張，依序共用單一 worker。
- 顯示每候選信心、有效字元、時間、總處理時間與候選一致數；高風險文字若只有單一不穩定低信心候選，沒有獨立強證據時最高先列 `SUSPICIOUS`。
- 使用者可中止；目前候選辨識中的 Tesseract 呼叫無法安全地在任意指令中點立刻終止，因此會在當輪結束後停止下一輪／下一張。

## 已知限制

- 無雲端 OCR、無 AI 超解析；不會猜測模糊筆畫。
- 尚未取得可重現的中低階 Android 實機 CPU／記憶體數據；本次只完成手機 viewport 與順序式記憶體防護，實機效能仍標為未驗收。
- 瀏覽器自動化環境無法把本機私有檔案交給 file chooser；因此實圖新流程需以專案擁有者手機再做最後 UAT，這不影響文字回歸與 production build 結果。
- 社群案例庫目前只有 1 筆去識別化案例；未命中不代表安全。
